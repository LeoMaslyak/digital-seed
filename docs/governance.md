# Personal AI Governance

Digital Seed is built around a simple belief: an assistant is only useful if it knows what it is optimizing for.

Governance here does not mean bureaucracy. It means giving your AI enough stable context to make better decisions and enough boundaries to avoid becoming noisy, invasive, or misaligned.

## The context stack

- `USER.md` — identity and background
- `COMPASS.md` — values, direction, priorities, operating principles
- `GOALS.md` — active objectives and milestones
- `DOMAINS.md` — projects, responsibilities, knowledge areas, recurring workflows
- `PREFERENCES.md` — how you like to work and communicate
- `ANTI-GOALS.md` — what not to chase
- `MEMORY.md` — durable facts, decisions, and lessons

## How the assistant should use this

For any meaningful request, the assistant should ask:

1. What does the user want right now?
2. Which context files are relevant?
3. Is this aligned with the user’s goals and anti-goals?
4. Is there a safer or more useful interpretation?
5. Should anything durable be remembered afterward?

## Anti-goals matter

Most productivity systems only track what you want. Digital Seed also tracks what you do not want.

Examples:

- Do not optimize for busyness.
- Do not create more tools than I can maintain.
- Do not make public claims without evidence.
- Do not automate sensitive personal communication without review.
- Do not let short-term urgency override long-term direction.

## Memory discipline

Do not save everything. Save things that will make future assistance meaningfully better:

- stable preferences
- repeated problems
- important decisions
- durable context
- lessons learned
- boundaries

Ask before saving sensitive facts.

## Review rhythm

Suggested cadence:

- Weekly: review `GOALS.md` and `DOMAINS.md`
- Monthly: review `COMPASS.md` and `ANTI-GOALS.md`
- Quarterly: prune stale memory and simplify the system

The system should get more useful over time, not heavier.
