# Digital Seed v0.4.1-alpha

## Summary

`v0.4.1-alpha` is an honesty, onboarding, privacy, and contributor-experience release for Digital Seed: a local-first personal AI context starter kit you can clone, edit, and use with terminal-capable AI agents.

This is a credible public alpha. It is **not** a 1.0 release candidate: real external-user validation is still the main blocker before any 1.0-flavored tag.

## What’s new

- Clearer first-15-minute path:
  - README now names the prerequisites up front: Git, Bun, and a terminal-capable AI agent.
  - The canonical start path is consistently `bun install` + `bun run seed onboard`.
  - `./setup.sh` is documented as an optional guided wizard, not the default day-one path.
- More beginner-friendly CLI output:
  - `bun run seed onboard --plain` now explains how to open the core context files and how to use the two-pane copy/paste flow.
  - `bun run seed first-prompt` now clearly marks exactly what to copy.
  - `bun run seed recipe list` shows one-line recipe descriptions instead of bare slugs.
- Stronger privacy and security honesty:
  - `SECURITY.md` and `user/README.md` now distinguish tracked starter templates from ignored personal files.
  - New `bun run seed hooks install` and `bun run seed hooks status` commands make the local pre-commit secret-scan hook explicit.
  - `bun run seed privacy-scan` warns when tracked starter templates look filled in with personal data.
  - `docs/what-leaves-your-machine.md` now documents Digital Seed’s own outbound network calls.
  - MCP servers are now described plainly as ordinary local processes, not sandboxed Digital Seed processes.
- Better open-source readiness:
  - Added `CODE_OF_CONDUCT.md`.
  - Added a recipe template at `recipes/_template/README.md`.
  - GitHub issue configuration now disables blank issues and routes questions/security reports to the right paths.
  - PR checklist sections are scoped so small docs fixes are not asked to run irrelevant heavyweight checks.
- Safer release engineering:
  - CI now runs on `v*` tag pushes.
  - CI pins Bun to `1.3.8` instead of `latest`.
  - `CHANGELOG.md`, `package.json`, and `docs/release-checklist.md` were kept aligned for `0.4.1-alpha`.

## Why this release matters

Digital Seed’s promise is intentionally modest: help someone get useful personal AI context locally, quickly, and without signing up for another platform.

This release makes that promise easier to trust. It removes beginner-path contradictions, tightens privacy caveats, makes contributor paths less intimidating, and records the simulated public-alpha audit that drove the fixes.

The result is a stronger public alpha: still small and customizable, but much less likely to confuse a stranger in the first 15 minutes.

## Known limits / not 1.0 yet

This is still alpha software.

Do **not** treat `v0.4.1-alpha` as production-grade OSS or a 1.0 release candidate. The real remaining 1.0 blocker is external validation:

- 5+ real external testers still need to run the first-15-minute path cold.
- Simulated hostile-user audits helped catch issues, but they do not count as real tester validation.
- Milestones 3, 4, and 5 readiness prep are shipped at the repo level, but the beginner path still needs outside-user proof.
- Advanced and maintainer commands remain intentionally outside the day-one trust contract.
- Windows-native remains out of scope; WSL2 is best-effort.
