# Digital Seed v0.4.3-alpha

## Summary

`v0.4.3-alpha` is a release-readiness and external-tester release. It keeps
the `0.4.x-alpha` trust contract, but makes the next step clearer: strangers
can now test Digital Seed with a non-technical guide, and maintainers have a
documented internal validation record for Codex CLI, Gemini CLI, Ollama, audit
history, CI, and release gates.

This is **not** a 1.0 release candidate. The hard gate remains real external
walkthroughs.

## What's new

**External tester path**
- `docs/external-tester-guide.md` — a non-technical tester guide with the exact
  path to try, privacy warnings, and a copy-paste feedback template for people
  who do not want to use GitHub.
- `bun run seed feedback` now points first-time testers at the guide and makes
  GitHub optional for basic feedback.
- README and `docs/feedback.md` link directly to the tester guide.

**Internal validation and audit documentation**
- `docs/agent-path-validation-2026-05-14.md` records internal Codex CLI,
  Gemini CLI, and Ollama validation.
- `docs/audit-log.md` indexes simulated audits, hostile audits, validation
  notes, and reusable audit prompts.
- `docs/public-usability-roadmap.md`, `docs/production-readiness.md`, and
  `docs/repo-improvement-roadmap.md` now distinguish internal validation from
  the external-user proof still needed.

**Release and maintainer cleanup**
- CI now uses Node 24-compatible GitHub actions:
  `actions/checkout@v5` and `actions/setup-python@v6`.
- The generated pre-commit hook avoids a macOS/BSD `grep` portability warning.
- `docs/releases/v0.4.2-alpha.md` was corrected to describe the current
  validation status honestly.

## Verification

- Tag: `v0.4.3-alpha`
- Release commit: current `main` at tag time.
- CI: passed on `ubuntu-latest` + `macos-latest`.
- Release check: `bun run seed release-check` passed locally before tagging.
- Fresh-clone harness: passed locally before tagging.
- Link check: all 74 Markdown files clean before tagging.
- Internal agent validation: Codex CLI and Gemini CLI can read the repo in
  headless/read-only checks; Ollama can run local model prompts.

## Known limits / not 1.0 yet

- Real external testers still have not walked the path. Zero outside
  walkthroughs have been recorded as of this release.
- Codex CLI and Gemini CLI are internally validated on a maintainer machine,
  but still need fresh-user walkthroughs.
- Ollama remains a local model runner, not a full file-editing agent by itself.
- Windows-native remains out of scope; WSL2 is best-effort.

## Recommended next steps

1. Invite 5+ real external testers using `docs/external-tester-guide.md`.
2. Capture every confusion point as a GitHub issue or docs patch.
3. Run a hostile audit against this release before considering another alpha
   polish pass.
4. Do not tag `1.0.0-rc.1` until external validation exists.
